Honest token counting
Character, word, line and byte counts are exact. Token counts are estimates: every model family splits text differently. OpenAI publishes its tokenizer (tiktoken); Anthropic and Google offer token-counting API endpoints, which need an API key, so this page uses per-family characters-per-token ratios instead. Expect English prose to land within roughly ±15%, and code or non-English text to vary more. For exact OpenAI counts use OpenAI’s tokenizer.

How to estimate LLM API costs before you commit

Model pricing shifts monthly, tokenizers differ per family, and every provider prices things a little differently — cached vs. fresh input, batch vs. real-time, short vs. very long prompts. This tool puts the current lineup on one monthly-cost view so you can compare like with like.

How the monthly figure is worked out

For each model: (fresh input tokens × input rate + cached input tokens × cache-read rate + output tokens × output rate) ÷ 1,000,000 × requests per month. Fresh input is your input tokens minus the cached share. If a request’s prompt is over a model’s long-prompt threshold (Anthropic Haiku 5.5: 100K; Google Gemini 3.1 Pro: 200K; xAI: 200K; OpenAI’s larger models: 272K), the higher rates apply to the whole request, as the providers bill it. Requests that don’t fit a model’s context window are flagged.

Why token counts are estimates (and why that’s honest)

OpenAI publishes its tokenizer (tiktoken); Anthropic and Google expose counting endpoints that need an API key; DeepSeek publishes a rough ratio. This page uses characters-per-token ratios: about 4 for OpenAI and Google on English text, about 3.3 for DeepSeek (its docs say 1 English character ≈ 0.3 tokens), and about 2.7 for current Claude models (roughly 3.5 on older ones, and Anthropic says its newer tokenizer produces about 30% more tokens for the same text). Real content varies with language, code density and punctuation.

What matters more than exact token counts

  • Input/output ratio. Chat apps skew toward long inputs and short outputs; code and reasoning models flip that. Output tokens usually cost 2–10× input, and reasoning models bill their hidden thinking as output.
  • Cached input. Reusing a long system prompt or document can cut input costs sharply: cache reads cost 2.5–50% of the normal input price depending on the provider and model. All five providers here publish cache-read prices.
  • Long prompts. Bigger context isn’t automatically more expensive per token, but several providers charge more once a prompt passes a threshold (see above). Watch the notes column.
  • Batch discounts. Anthropic, OpenAI and Google publish batch prices, usually 50% off for jobs that can wait up to a day. Tick “Use batch prices” to compare; models without published batch prices stay at standard rates and are marked.
  • Off-peak and introductory prices. DeepSeek halves its prices outside weekday business hours in China (listed here at the higher, peak rate). Some Google and OpenAI prices are introductory with an announced end date; the table switches to the announced price on that date.

Data source and freshness

Prices are copied from each provider’s own pricing page and stored in llm-pricing.json with the provider’s pricing URL and the date they were checked (shown at the top of the tool). Retired and no-longer-listed models are removed at each refresh; we aim to refresh quarterly. If you spot a stale figure, the source link is one click away. Never trust an AI-written pricing summary (including one from us) without checking the provider’s page.
